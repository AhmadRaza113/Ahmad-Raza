## 1. Purpose

This document defines the **frontend ↔ backend HTTP + SignalR data contract** for the
`<sheet-grid>` web component.  
It is derived from actual frontend source code and should be used by:

- Backend (Azure Functions) implementors as the canonical expected wire format
- Frontend developers making API-related changes
- QA / integration testers
- AI coding agents modifying API or state code

---

## 2. Scope

Covers:

- HTTP endpoints called by the frontend (path, method, request body, expected response)
- SignalR hub events received and emitted
- Row data model and normalization rules
- Lock, typing, and conflict message shapes
- Column `colId` definitions and mapping notes

Does **not** cover:
- Internal backend SQL/DB schema
- Azure Function implementation details (not in repo)
- UI rendering specifics (see `docs/grid/rendering-and-virtualization.md`)

## 4. Base URL Contract

**Code-proven** (`src/component.js`, `src/api/client.js`):

```js
get apiBase() { return (this.getAttribute("api-base") || "").replace(/\/+$/, ""); }
// Usage: `${this.apiBase}${path}` where path starts with "/api/..."
```

- The `api-base` attribute must be set to the **Azure Function App root URL**,
  **without** a trailing `/api` segment.  
  Example: `https://my-func.azurewebsites.net` (not `…/api`).
- The code strips trailing slashes from `api-base`, so `https://host/` and
  `https://host` are equivalent.
- All endpoint paths below begin with `/api/…` and are appended directly to `apiBase`.

## 5. Core Row Model

### 5.1 API row shape (as returned by server)

**Frontend-observed contract** (`src/api/rows-api.js`):

```jsonc
{
  "id":        "<string>",          // unique row identifier — used as map key
  "clientId":  <number>,
  "rowVer":    <number|opaque>,     // concurrency token — see §6
  "updatedAt": "<ISO 8601 string>",
  "updatedBy": "<userId string>",
  "values": {                       // flat colId→value map
    "<colId>": <string|number|null>,
    // ...
  },
  "reqNo":   <number|null>,         // optional; top-level; auto-generated by server
  "seqNum":  <number|null>          // optional; top-level; auto-generated by server
}
```

### 5.2 Frontend in-memory row shape (post-normalization)

**Code-proven** (`src/api/rows-api.js` `_loadRowsFromServer`):

```jsonc
{
  "id":        "<string>",
  "clientId":  <number>,
  "rowVer":    <number|opaque>,
  "updatedAt": "<ISO 8601 string>",
  "updatedBy": "<userId string>",
  "values": {
    // all colId→value pairs from server values object,
    // PLUS the following remapped fields:
    "req_no":  <number|null>,   // mapped from top-level `reqNo`  (note underscore)
    "seqNum":  <number|null>    // mapped from top-level `seqNum` (same key name)
  }
}
```

## 6. Row Normalization Behavior

**Code-proven** (`src/api/rows-api.js` `_loadRowsFromServer`, `_refreshSingleRow`;
`src/live/handlers.js` `_onGridRowAdded`):

| Source field | Mapping | Notes |
|---|---|---|
| `row.values` | spread into `values` directly | all other `colId` keys preserved |
| `row.reqNo` | → `values.req_no` | only if `reqNo != null`; note key rename (`reqNo` → `req_no`) |
| `row.seqNum` | → `values.seqNum` | only if `seqNum != null`; key name unchanged |
| `row.id` | `row.id` | used as `_rowMap` key; type: string |
| `row.clientId` | `row.clientId` | stored; used for SignalR event filtering |
| `row.rowVer` | stored in `row.rowVer` and `_rowVer` Map | see §7 |
| `row.updatedAt` | stored in `row.updatedAt` | ISO string |
| `row.updatedBy` | stored in `row.updatedBy` | userId string |

**`_normalizeState`** (`src/state/normalize.js`): reconciles `columnOrder` and
`rowOrder` arrays with actual loaded data after each fetch. Does **not** transform
row values; only manages ordering arrays and default column widths.

**`_onGridRowAdded`** note: only maps `reqNo` → `values.req_no`; does **not** map
`seqNum`. If server includes `seqNum` in a `gridRowAdded` event, it must be nested
inside `row.values.seqNum` for it to appear — **needs verification** (see §14).

## 7. `rowVer` Concurrency Contract

**Code-proven** (`src/api/cells-api.js`, `src/api/rows-api.js`,
`src/live/handlers.js`):

- `rowVer` is stored per-row in `this._rowVer` Map (`rowId → rowVer`).
- Sent to server as `baseRowVer` in every batch save update item.
- Initial value before first fetch: `null`.
- Compared using `Number()` coercion in `_refreshSingleRow`:
  ```js
  Number(fresh.rowVer) <= Number(existing.rowVer)  // skip if not newer
  ```
- Updated on: successful batch save (`r.rowVer`), conflict response
  (`r.currentRowVer`), `gridPatch` event (`msg.rowVer`).

**Type assumption:** Frontend coerces to `Number()` — treats as numeric.
However, `baseRowVer` is sent as-is (not stringified further), so if the server
returns it as a string, `Number()` coercion still works for comparison.  
**Treat as opaque** unless backend explicitly guarantees integer semantics; do
not increment client-side.

All paths are relative to `apiBase`. The `_api()` wrapper sends
`Accept: application/json`; POST bodies include `Content-Type: application/json`.
Credentials: `omit`.

| 4 | POST | `/api/auditorRequests/rows` | Add new row |

## 9. Endpoint Details

### 9.1 Load All Rows

**Code-proven** (`src/api/rows-api.js` `_loadRowsFromServer`).

**Request:**
```
GET /api/auditorRequests?clientId={clientId}
```
- `clientId`: URL-encoded number (from `encodeURIComponent(this.clientId)`)

**Response consumed:**
```jsonc
{
  "ok":    true,
  "rows":  [ /* Array<ApiRow> — see §5.1 */ ],
  "error": "<string>"  // present on failure (ok: false)
}
```

**Notes:**
- Frontend checks `json?.ok`; if falsy, throws `json?.error || "Failed to load rows"`.
- `rows` key defaults to `[]` if not an array.
- Triggers full state reset: `_pending`, `_conflicts`, `_locks`, `_remoteTyping` all cleared.

**Verification status:** Frontend-observed contract.

---

### 9.2 Single-Row Refresh

**Code-proven** (`src/api/rows-api.js` `_refreshSingleRow`).

**Request:**
```
GET /api/auditorRequests?clientId={clientId}&rowId={rowId}
```
- `rowId`: URL-encoded string.

**Response consumed:** Same shape as §9.1.

**Notes:**
- Server **may** return just the one matching row or all rows — frontend finds the
  matching row via `rows.find(r => r.id === rowId)`.
- Skips update if `fresh.rowVer <= existing.rowVer` (i.e., server hasn't advanced).
- Silently ignores errors (non-critical fallback path).
- Also called inline inside `_onGridTyping` (after 450 ms typing-clear delay).

**Verification status:** Frontend-observed; whether `rowId` param is server-side
filtered is **unknown** — **needs verification** (§14).

---

### 9.3 Batch Cell Save

**Code-proven** (`src/api/cells-api.js` `_flushPending`).

**Request:**
```
POST /api/auditorRequests/batch
Content-Type: application/json
```
```jsonc
{
  "clientId": <number>,
  "byUser":   "<userId>",
  "updates": [
    {
      "rowId":      "<string>",
      "colId":      "<string>",
      "value":      <any>,
      "baseRowVer": <number|null>   // from _rowVer Map; null if never fetched
    }
    // ... up to serverFlushBatchMax (40) items; at most one per rowId per call
  ]
}
```

**Constraints (code-proven):**
- At most **one update per `rowId`** per flush call (additional updates for the same
  row are deferred to the next flush).
- Maximum batch size: `this.config.serverFlushBatchMax` = **40** items.
- Debounce: `serverFlushDebounceMs` (see `src/config/defaults.js`).

**Success response consumed:**
```jsonc
{
  "ok": true,
  "results": [
    {
      "rowId":     "<string>",
      "colId":     "<string>",
      "updated":   true,
      "value":     <any>,          // server-confirmed stored value
      "rowVer":    <number>,       // new rowVer after update
      "updatedAt": "<ISO string>",
      "updatedBy": "<userId>"
    }
    // ...
  ]
}
```

**Conflict result variant (within `results`):**
```jsonc
{
  "rowId":              "<string>",
  "colId":              "<string>",
  "conflict":           true,
  "currentValue":       <any>,          // server's current value
  "currentUpdatedAt":   "<ISO string>",
  "currentUpdatedBy":   "<userId>",
  "currentRowVer":      <number>        // server's current rowVer
}
```

**On conflict:** frontend stores conflict entry, updates local row to server's
current value + rowVer, shows toast, renders cell with `"conflict"` CSS class.

**Failure response consumed:**
```jsonc
{ "ok": false, "error": "<string>" }
```

**`beforeunload` variant:** The global-wiring code sends pending batch via
`navigator.sendBeacon` using a `Blob` with `type: "application/json"` — **needs
backend verification** that the server parses Blob-wrapped JSON correctly (§14).

**Verification status:** Request shape code-proven; response shape frontend-observed.

### 9.6 Lock Acquire

**Code-proven** (`src/api/locks-api.js` `_acquireLock`).

**Request:**
```
POST /api/locks/acquire
Content-Type: application/json
```
```jsonc
{
  "clientId":   <number>,
  "rowId":      "<string>",
  "colId":      "<string>",
  "userId":     "<string>",
  "ttlSeconds": 30            // from config.lockTtlSeconds
}
```

**Success response consumed:**
```jsonc
{ "acquired": true }
```

**Failure response consumed:**
```jsonc
{
  "acquired": false,
  "holder": {
    "userId":        "<string>",
    "acquiredAtUtc": "<ISO string>",  // optional
    "ttlSeconds":    <number>          // optional
  }
}
```

**Notes:**
- If `acquired: false` and `holder.userId === this.userId`, frontend treats as own
  lock (recovery path).
- `holder` object spread into `_locks` Map with added `owned` boolean.

**Verification status:** Code-proven (request + response shapes both read in code).

### 9.9 Typing Broadcast

**Code-proven** (`src/api/typing-api.js` `_broadcastTyping`).

**Request:**
```
POST /api/typing
Content-Type: application/json
```
```jsonc
{
  "clientId": <number>,
  "rowId":    "<string>",
  "colId":    "<string>",
  "userId":   "<string>",
  "value":    "<string>"   // current typed string; "" means "stopped typing"
}
```

**Timing:**
- Debounced at **150 ms** (`_broadcastTypingDebounced`).
- On commit: explicit `value: ""` sent after **200 ms** delay (to let `gridPatch`
  arrive first).
- On cancel: explicit `value: ""` sent immediately.
- On `beforeunload`: sent via `navigator.sendBeacon` as plain JSON string (no Blob).

**Response:** Not consumed (fire-and-forget; errors silently ignored).

**Verification status:** Request shape code-proven; response shape unknown.

|---|---|---|

## 11. Column `colId` Definitions and Mapping Notes

**Code-proven** (`src/config/columns.js` `DEFAULT_COLS`):

| `colId` | Display Name | Type | Read-Only | Width |
|---|---|---|---|---|
| `auditor_request` | Auditor's Request | multiline | no | 300 |
| `host_comments` | Host Comments | multiline | no | 260 |
| `host_backroom_comments` | Host/Backroom comments | multiline | no | 300 |
| `assigned_to` | Assigned To | person | no | 190 |
| `status` | Status | choice | no | 150 |
| `requested_department` | Requested Department | choice | no | 210 |
| `request_type` | Request Type | choice | no | 170 |
| `due_datetime` | Due Date/Time | datetime | **yes** | 190 |
| `client_name` | Client Name | text | **yes** | 190 |
| `closed_time` | Closed Time | datetime | **yes** | 190 |
| `completed_on` | CompletedOn | datetime | **yes** | 190 |
| `client_id` | Client ID | number | **yes** | 120 |

**Synthetic keys added by frontend normalization (not in `DEFAULT_COLS`):**

| Key in `values` | Mapped from | Notes |
|---|---|---|
| `req_no` | top-level `reqNo` | read-only; display-only |
| `seqNum` | top-level `seqNum` | used for default sort (ascending); filtered out of persisted sorts |

**Backend alignment notes:**
- The `values` object stored in the DB must use the same `colId` keys listed above
  for editable columns.
- `req_no` and `seqNum` are **server-generated** auto fields; frontend never writes
  them back as part of a batch save (they are not in the editable column set).
- Read-only columns (`due_datetime`, `client_name`, `closed_time`, `completed_on`,
  `client_id`) have `readOnly: true`; frontend will not acquire locks or send batch
  saves for these columns.

## 12. Conflict Data Shape (Internal Frontend State)

**Code-proven** (`src/api/cells-api.js`, `src/live/handlers.js`):

```jsonc
// Stored in _conflicts Map under key `"${rowId}|${colId}"`
{
  "rowId":         "<string>",
  "colId":         "<string>",
  "mine":          <any>,           // frontend's unsaved value at conflict time
  "server":        <any>,           // server's current value
  "updatedAt":     "<ISO string>",  // server's updatedAt
  "updatedBy":     "<userId>",      // who made the conflicting change
  "currentRowVer": <number>         // server's current rowVer
}
```

Conflict entries are cleared when: user chooses "Keep mine" or "Accept server" in the
conflict modal, or when a `gridPatch` arrives confirming the cell, or when the row is
deleted.

- [ ] Update this file (`docs/grid/data-contracts.md`)

- [ ] Verify batch constraint (one update per `rowId` per call) is still respected
- [ ] Verify `rowVer` is returned in all successful batch `results` items
- [ ] Verify conflict response includes `currentRowVer`, `currentValue`,
      `currentUpdatedAt`, `currentUpdatedBy`
- [ ] Verify lock acquire failure returns `holder.userId` (used for own-lock recovery)
- [ ] Verify lock renew returns `renewed` boolean
- [ ] Verify negotiate returns `url` + `accessToken` (both required)

      `gridTyping` event names match backend broadcast names exactly

## 14. Needs Verification (Requires Azure Function Code)

| Unknown | Impact | Notes |
|---|---|---|
| Whether `GET /api/auditorRequests?rowId=...` actually filters server-side | Medium | Frontend handles full-array response gracefully (scans for matching `id`), but extra data is wasteful |
| `sendBeacon` handling for **lock release** (plain JSON string body, no `Blob`) | High | If server requires `Content-Type: application/json`, a plain string beacon may be rejected silently |
| `sendBeacon` handling for **typing clear** (plain JSON string body) | Medium | Same concern as above |
| `sendBeacon` for **batch save** uses `Blob` with `type: "application/json"` | Medium | Confirm server accepts Blob-wrapped JSON |
| `rowVer` exact type from DB (SQL `rowversion`? integer counter?) | Medium | Frontend uses `Number()` coercion — works for integers and numeric strings; fails for hex binary rowversion |
| Whether `gridRowAdded` message includes `seqNum` as top-level or inside `values` | Medium | `_onGridRowAdded` maps `reqNo` only; `seqNum` must be inside `values` or it is lost |
| Hub name for Azure SignalR Service | Low | Embedded in negotiate `url`; not visible in frontend |
| Exact DB schema (table names, column types, indexes) | Low for frontend | No backend source in repo |
| Server-side lock storage mechanism (Redis mentioned in `component.js` header comment) | Low | Header comment says "Redis locks" — not verifiable from frontend |
| `reqNo` generation logic (auto-increment? per-client?) | Low | Frontend treats as read-only display field |
| `seqNum` generation logic | Low | Frontend uses for default sort; never written by frontend |
| Lock TTL cleanup on server disconnect (TTL expiry vs active cleanup) | Low | Frontend relies on TTL; disconnect cleanup is server-side |
| Exact server error response shape | Low | Frontend reads `json?.error` without enforcing shape |
